Start with the local service.

Sherlock runs on your computer and connects to an agent through the Model Context Protocol (MCP). You need Python 3.11 or newer, uv, and an agent host that can launch a local MCP process. Your host supplies the model and research tools.

  1. Get the source and install the runtime. The repository includes the Python package, a locked dependency file, and the skill files. Use the commands below from the repository root.
  2. Check the local setup and try fictional data. Run the documented doctor and demo commands before connecting any provider. The examples let you inspect case storage and recall with no CRM credentials.
  3. Connect your agent and load the skills. Configure the host to launch Sherlock’s MCP service, then install the workflow skills using that host’s documented method. Keep the runtime path absolute in host configuration.

From the repository root, run these commands in a macOS or Linux terminal:

uv sync --project public-facing/runtime --frozen
uv run --project public-facing/runtime sherlock doctor
uv run --project public-facing/runtime sherlock demo

Doctor should report local storage as ready. The demo should return clearly labeled fictional cases and recall results from its separate demo profile. Data goes into Sherlock’s local application-data directory, outside the source checkout.

Give this setup prompt to your agent

Replace the source path with your checkout’s absolute path, then paste this into the local agent you want to use:

What is in the alpha?

The source bundle includes seven skill files and a local Python MCP service. The skills guide the work; the service supplies persistent case evidence, recall, and controlled CRM workflows. Read the setup guide for the current command and tool contracts.

  • Agent Sherlock chooses the appropriate workflow and establishes evidence and permission rules.
  • Competitor research turns available public sources into a dated, sourced brief.
  • Account context matches records and manages proposed CRM changes.
  • Case files preserves evidence, corrections, and investigation history.
  • Recall retrieves prior evidence for an answer or another agent.
  • Dormant relationships reviews actual pitched contacts still at the same company after scoped contact dormancy.
  • Pitched contact moves reviews actual pitched contacts verified at a new employer.

The relationship guide covers portable imports, local owner feedback, and explicitly enabled host schedules. Sherlock does not collect Sales Navigator data or send outreach.

Live provider connections are optional and must be configured separately. A configured connector is not evidence that authentication, permissions, or a real read-and-write workflow has passed. The compatibility notes explain that boundary.

Work with Sherlock in Slack

A host with its own Slack integration can make Slack the place your team asks Sherlock questions. For example: who have we worked with across medical, finance, automotive, or another industry? The answer comes from the history and context available to the host and the selected Sherlock profile.

That makes recall useful in an ordinary conversation: find relevant past clients, count recorded engagements, or bring project experience into a pitch. The answer depends on which records are available; a missing record should not be treated as proof that the work never happened.

See the Slack conversation examples. The screenshots use fictional names, counts, and project descriptions. Their answer format illustrates the intended public experience.

This source bundle does not install a Slack app or import workspace history. Slack delivery, workspace access, and channel permissions belong to your configured host. Connecting the local MCP service does not connect Slack.

Investigate competitors’ social presence

Start with a company, its competitors, verified public accounts, and a question or time window. The competitor research skill guides your host through the sources it can access and produces a brief with findings, source links, open questions, and ideas to test.

  • Organic content: compare topics, formats, hooks, calls to action, and posting patterns.
  • Community: examine public audience questions, objections, and brand responses.
  • Paid creative: compare visible ad concepts and messages where public evidence is available.
  • Next steps: turn supported findings into focused content and strategy experiments.

Sherlock’s local service does not include a web crawler or model. Your host can use its own research tools or sources you provide. Unavailable, restricted, failed, and unattempted sources remain explicit; they do not mean a competitor has no activity.

Sources and dates belong with the findings. Public ads alone do not establish spend, targeting, conversions, or return on ad spend. Separate source claims, observations, inferences, and recommendations.

Keep leads and accounts in context

Research a lead or company, connect the findings to the right existing record, and keep useful facts close to the next account conversation. Social research is one source of that context; company and contact research also matter.

The account context skill reads a configured connection, resolves the correct record, and prepares field-level changes with supporting evidence. External changes require approval of the specific proposal unless an active, explicit policy already covers that provider, account, action, and fields.

A proposal has not been saved to the CRM. A provider acknowledgment and a verified destination readback are separate outcomes. Use Sherlock’s controlled workflow and report its actual result.

In the approval-required workflow, review the exact proposal in your own terminal before the agent applies it. The MCP agent cannot approve its own proposal. The account recipe explains this step.

Connections are not enabled by installing the skills. Configure credentials and permissions outside the repository, then verify the selected account and supported operations before using a provider. Live provider and host tests are separate from the local test suite.

Build a living case file

A case file keeps the research around a company or question together: facts, social signals, source links, account history, open questions, and the next useful action.

The local service stores evidence in a profile on your computer. Reuse the correct case as an investigation develops, record observation dates and provenance, and preserve corrections through the supported case tools. After saving, read the case back to confirm the intended evidence is present.

Keep unrelated customers or teams in separately configured profiles. A shared local profile is a shared data boundary; it is not per-user access control. Exported cases and backups are additional copies of the same information.

Remember for the rest of your agents

Recall retrieves the relevant facts from earlier work. A strategy agent might need the last competitor brief, a content agent the creative patterns, and a sales agent the account history.

The recall skill retrieves facts with their source, observation time, case reference, and uncertainty. Inspect the underlying evidence before making a precise claim. Older observations are dated context, not proof of the current situation.

A search result is not a complete client census. Distinguish companies from engagements, check coverage, and label fictional fixtures. No relevant result means nothing matching was found in the searched material.

Retrieving context does not deliver it to another person or agent. Your host handles any separately authorized handoff. See the agent compatibility notes.

Built to work with your agents

Sherlock supplies a local MCP service and portable Markdown skill files. Host support depends on whether your agent can launch that service and how it loads skills. Each host needs its own installation instructions and verification.

Claude Code, ChatGPT, Hermes Agent, and OpenClaw are compatibility targets. Their names are not a claim that every host, product tier, or connection method has been tested. A hosted chat interface may require a remote connector that this local setup does not provide.

Verify the actual host connection. Confirm that the host can list Sherlock’s tools, read its status, save fictional evidence, and retrieve that evidence before relying on the setup. Real research, Slack, and CRM access each need their own checks.

The compatibility record distinguishes documented setup, protocol and fixture tests, host tests, and live provider reads and writes.
